Replikrazy

Plan static-site mirrors in your browser. Dry run and manual export only — nothing is uploaded or deployed.

1. Load a static site

Files stay in this tab. HTML and scripts in the bundle are never opened or run. The first read establishes a content snapshot; repeated reads must match it. To load later edits, select the site again.

2. Inventory

The artifact id is a SHA-256 over the file list, app id and entry page. The same files always give the same id, whether loaded from a folder or a ZIP. It identifies content; it is not a publisher identity or a signature.

          5. Dry-run plan

          Intended use (your declaration; it sets policy checks)

          Payment and token/key apps are blocked on every destination until one is qualified for them. The scan cannot prove a bundle is free of secrets.

          Handoff ZIP: app/ (exact bytes, the only part to upload) plus mirrorkit-control/ (manifest, plan, scan, instructions — never upload).           6. Compare a copy (optional)

          After publishing, save the mirror's files with your own tools and load them here to compare against the original. Nothing is downloaded by Replikrazy.

          7. Inspect recovery metadata (optional)

          Read a saved recovery JSON file locally (up to 10 MiB). This view does not restore files, statuses, consent or plans. It does not contact providers. Treat records and signatures as untrusted claims.

          Recovery metadata does not include site file contents. To continue working with an artifact, load its matching ZIP or folder in step 1.
