Offline Mirror Planner

Inventory a static-site folder on this computer, describe the mirror destinations you intend to set up yourself, compare what you have declared, and export a deployment plan with operator instructions and inert configuration templates.

The planner scripts did not load. Keep all files of the tool together (index.html next to the src folder) and open index.html in a current browser with JavaScript enabled.

This is a planner and offline exporter — never a publisher

  • Nothing is uploaded, published, deployed, registered or verified. This page has no way to contact any host, provider, Tor or I2P network.
  • No network requests. The page's Content-Security-Policy forbids them; all work happens inside this browser tab.
  • Every address and capability is declared by you and stays unverified. The best possible state is "ready for manual review", never "verified" or "live".
  • It never signs up anywhere, never creates Tor or I2P keys, identities or addresses, and never starts or configures any service. Templates it exports are inert text for a person to review.
  • State is kept in memory only — no localStorage, IndexedDB, cookies or other browser storage. Reloading or closing this tab discards everything; export what you want to keep.
Limitations you should know about

    1. Site folder

    Select the folder that contains the built static site (the folder with index.html). Files are read and hashed (SHA-256) inside this tab. Sensitive files — credentials, private keys, onion/I2P key material, wallets, databases, backups, version-control and OS metadata — are excluded without being read.

    Limits

      2. Destinations

      Describe each place you intend to mirror the site. Everything you enter is a declaration for planning; nothing is looked up or contacted. Capabilities default to "unknown" — confirm each one from the destination's own documentation or configuration before declaring it.

      3. Compare destinations

      How each destination's declared capabilities meet what this site and plan require. Nothing here is verified.

      4. Headers & settings

      Response headers every destination should send

      Strict-Transport-Security and Onion-Location are added per destination automatically and must not be listed here. Credential-bearing and connection-level headers are refused.

      Onion-Location

      Warning: an Onion-Location header publicly and permanently links your clearnet mirror(s) to the onion address. Anyone can see that both are run by the same operator. Only enable this deliberately.
